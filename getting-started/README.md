# Getting started

**Status:** Implemented — the introductory pages describe the system as it exists; individual pages label planned parts.

Start here if you are new to Avalon. These pages explain what Avalon is, why it exists, and the handful of concepts every other page builds on. They assume no prior knowledge of the project.

## Reading order

1. [What is Avalon?](what-is-avalon.md) — a one-page description of the system and what it is not.
2. [Why Avalon](why-avalon.md) — the problem, what already exists, and the gap Avalon fills.
3. [Concepts](concepts.md) — a one-page tour of the core ideas, each linking into the architecture and protocol pages.
4. [For users](users.md) — if you use games, apps, or services that integrate Avalon and want to know what that means for you.

If the vocabulary is the obstacle, keep the [glossary](../reference/glossary.md) open. Most of the difficulty on a first read is precise terms (integrator, issuer, node, authentic, valid, recognized), not the ideas.
